# CoolMap AI — 냉난방 쉼터 지도

> A tool that helps people find public shelters to evacuate from the stunning heat and cold (South Korea Only)

폭염·한파에 대응하는 **주변 냉난방 쉼터 지도** 데스크톱 앱입니다.
웹앱이 아닌 Windows 네이티브 앱(Python + PySide6/Qt)으로 동작합니다.
지도는 OpenStreetMap 타일, 날씨는 기상청 실측, 민폐도는 Gemini가 산출합니다.

```
python main.py        또는   run.bat 더블클릭
```

## 설치

```bash
pip install -r requirements.txt   # PySide6
python main.py
```

Python 3.10 이상 / Windows 10·11에서 확인했습니다. (개발·검증 환경: Python 3.14, PySide6 6.11)

## 데이터 연동 현황

| 항목 | 출처 | 상태 |
|---|---|---|
| 지도 타일 | OpenStreetMap | ✅ 실데이터 (키 불필요) |
| 건물 외곽선 | OSM Overpass API | ✅ 실데이터 (키 불필요) |
| 날씨 | 기상청 초단기실황 · 단기예보 | ✅ 실데이터 (CoolMap 서버 경유) |
| 민폐도 | Google Gemini | ✅ 실데이터 (CoolMap 서버 경유) |
| 혼잡도 | 실시간 인구 데이터 | ⏸ **Coming Soon** — UI 비활성 |
| 쉼터 (냉방) | 행안부 무더위쉼터 `DSSP-IF-10942` | ✅ 실데이터 **전국 61,767곳** (CoolMap 서버 경유) |
| 쉼터 (난방) | 행안부 한파쉼터 `DSSP-IF-10804` | ✅ 실데이터 **전국 53,025곳** (CoolMap 서버 경유) |
| AI 추정 쉼터 | OSM 상호 + Gemini 판단 | ✅ 실데이터 (CoolMap 서버 경유) |
| 현재 위치 | Qt Positioning (윈도우 위치 서비스) | ✅ 실데이터 (키 불필요) |

**API 키 없이 바로 실행됩니다.** 쉼터 목록 · 날씨 · AI 는 CoolMap 서버(Supabase)가
대신 받아 두거나 대신 호출합니다. 자세한 구조는 아래 [CoolMap 서버](#coolmap-서버-supabase) 참고.

### 본인 API 키 사용 (선택)

본인 키를 넣으면 서버 대신 그 키로 직접 받습니다. 키는 **소스에도 실행 파일에도 넣지 않습니다.**
아래 중 하나로 지정하세요.

1. 환경변수 `COOLMAP_GEMINI_KEY`, `COOLMAP_KMA_KEY`,
   `COOLMAP_SHELTER_KEY`, `COOLMAP_COLD_SHELTER_KEY`
2. `%APPDATA%\CoolMap\secrets.json`
3. 앱 실행 후 **설정 > API 키** 에서 직접 입력 (배포판 권장)

```json
{
  "gemini_api_key": "…",
  "kma_service_key": "…",
  "shelter_service_key": "…",
  "cold_shelter_service_key": "…"
}
```

무더위쉼터와 한파쉼터는 **서로 다른 서비스**라 인증키도 따로 발급받아야 합니다.

`kma_service_key` 는 공공데이터포털(data.go.kr) 일반 인증키,
`shelter_service_key` 는 재난안전데이터공유플랫폼(safetydata.go.kr) 인증키입니다.
Encoding 값(`%2B` 등이 포함된 형태)을 넣어도 자동으로 디코딩합니다.

서버에도 연결할 수 없으면 쉼터는 저장해 둔 목록(없으면 데모 데이터)으로, 날씨는 모의 곡선으로,
민폐도는 규칙 기반으로 폴백합니다. 네트워크가 끊기면 지도는 캐시된 타일을 쓰고, 없으면 오프라인 안내를 표시합니다.

### 캐시

`%APPDATA%\CoolMap\cache\` 에 타일·건물·날씨·민폐도를 저장합니다.
설정 → 데이터 연동 상태에서 현황 확인과 캐시 비우기가 가능합니다.

## 주요 기능

### 1. 냉방 · 난방 모드
- **냉방 모드**: 푸른 계열(시안) 테마 — 폭염 대응, 시원한 쉼터를 찾습니다.
- **난방 모드**: 붉은 계열(오렌지-레드) 테마 — 한파 대응, 따뜻한 쉼터를 찾습니다.
- 전환하면 앱 전체 색상, 지도 색, 추천 목록, 대상 쉼터가 모두 바뀝니다.
  (예: `새벽전통시장 온열쉼터`는 난방 모드에서만, `별빛 시네마`는 냉방 모드에서만 노출)
- 사이드바 하단 **모드 전환** 버튼, 홈의 **Active Mode** 카드, 상단 바 아이콘 어디서나 전환할 수 있습니다.

### 2. AI 혼잡도(사람 수) 예측 — ⏸ Coming Soon

실시간 인구 데이터 연동 전이라 **비활성 상태**입니다.
상세 화면의 혼잡도 카드는 `COMING SOON` 배지와 함께 회색으로 표시되고,
쾌적 점수·추천 정렬도 혼잡도를 배제하고 계산합니다.

예측 엔진(`ai.py`)은 그대로 남아 있으며, `CROWD_ENABLED = True` 한 줄로 되살아납니다.
그때 이벤트 영향권에 든 쉼터는 **“사람이 이벤트로 인해 많아요”** 로 표시됩니다.

지금은 행사 정보만 사실 그대로 안내합니다 —
지도에 노란 점선 원으로 영향권을 표시하고, 카드에는
“인근에서 행사가 진행 중이에요 (평소보다 붐빌 수 있음)” 로 안내합니다.

### 3. 민폐도 지수 (0~100) — Gemini 산출
"오래 있으면 눈치 보이는 정도"를 수치화합니다. 낮을수록 편하게 오래 머물 수 있습니다.

**Gemini(`gemini-3.5-flash`)** 가 시설 성격·구매 필요 여부·좌석 수·공식 쉼터 지정 여부·운영시간을
고정 루브릭에 따라 평가합니다. 실제 산출 예시:

**공식 지정 쉼터라도 시설의 '본래 목적'과 어긋나면 눈치가 보인다**는 점을 루브릭에 명시했습니다.
볼일 없이 은행 로비에 앉아 있는 상황을 실제로 반영합니다.

| 장소 | 민폐도 | 권장 체류 |
|---|---|---|
| 야외 그늘쉼터 | 10 | 2시간 |
| 도서관 · 주민센터 | 15 | 3시간 |
| 경로당·마을회관 | 50 | 30분 |
| 은행·새마을금고 | 65 | 20분 |
| 편의점 | 75 | 20분 |

- 등급: `매우 자연스러움 / 자연스러움 / 보통 / 눈치 보임 / 매우 눈치 보임`
- 이유 한 줄과 실용적인 팁 2~3개를 함께 제공합니다.
- `temperature 0` + 고정 루브릭 + 캐시로 값이 흔들리지 않게 했습니다.
- 쉼터가 6만 곳이라 장소마다 호출할 수 없어, **시설 '유형' 단위로 캐시**합니다
  (유형·공식지정·구매필요·규모 조합). 실제로 60곳 → 14회 호출로 압축됩니다.
- **측정값이 아닌 추정치입니다.** Gemini 를 쓸 수 없으면 규칙 기반 계산으로 폴백합니다.

### 4. 지도 표시 방식 — 하이라이트 vs 화살표
- **건물 하이라이트**: 쉼터가 속한 **실제 건물 외곽선**(OSM Overpass)을 통째로 강조합니다.
  은행·금융기관처럼 큰 건물에 입점한 시설도 건물 전체를 칠합니다 —
  대형 상가·오피스는 실내 전체가 냉방되는 경우가 많아 건물 단위 표시가 더 유용합니다.
  건물 데이터가 없거나 축소 상태(z<14.5)에서는 원형 하이라이트로 대체됩니다.
- **화살표 지시**: **층·호수까지 아는** 경우에만 정확한 지점을 곡선 화살표로 가리키고
  `B1`, `2F` 같은 층 배지를 붙입니다. (무더위쉼터 원본에는 층 정보가 없어 실데이터에서는
  거의 쓰이지 않고, 설정에서 '항상 화살표'로 강제할 수 있습니다.)
#### 다크맵 렌더링

OSM 원본은 밝은 지도라 그대로 쓰면 앱과 안 어울립니다. 밝기를 추출해
**모드별 색 램프(어두운 배경색 → 밝은 선·글자색)로 재배치**합니다.
픽셀 연산은 파이썬으로 감당이 안 되므로 Qt 의 인덱스 컬러 테이블(256단계)로
한 번에 매핑합니다.

감마를 1 보다 크게(`1.35`) 두는 것이 핵심입니다. 넓은 지면(원본의 밝은 부분)은
어둡게 눌리고 도로·지명(원본의 어두운 선)은 밝게 남아, 배경은 다크 UI 와
어울리면서도 글자가 읽힙니다. 1 미만으로 두면 배경까지 들려 전체가 뿌옇게 됩니다.
`providers/tiles.py` 의 `RAMPS` · `RAMP_GAMMA` 로 조절합니다.

마커는 지도 위 어디에 놓여도 분리돼 보이도록 **어두운 테두리를 먼저 깔고**
그 위에 강조색을 올립니다 (건물 외곽선 · 화살표 · 라벨 칩 · 지시선 모두 동일).

- **설정 → 지도 표기 방식** 또는 지도 화면 좌상단 패널에서 언제든 변경할 수 있습니다.
  - `자동` (기본): 층 정보가 있으면 화살표, 없으면 건물 전체 하이라이트
  - `항상 건물 하이라이트`
  - `항상 화살표로 지시`

### 5. AI 추정 쉼터 — 지도의 상호를 읽어 추가 하이라이트

지도에는 `하나로마트`, `○○도서관` 처럼 상호가 찍혀 있는데 행정안전부 공식
목록에 없으면 앱에서는 아무 표시도 되지 않습니다. 사용자 눈에는
"저기 분명 시원할 텐데 왜 안 뜨지?" 로 보입니다.

그 이름표의 원본(OSM POI)을 가져와 **Gemini 가 상호명과 시설 종류를 읽고
'볼일 없이 들어가 있어도 되는 냉난방 실내 공간인지' 판단**합니다.
맞다고 보면 지도에 **점선**으로 덧붙입니다.

```
공식 지정 쉼터   ─ 실선 + 채운 하이라이트
AI 추정 쉼터     ┄ 점선 + 옅은 하이라이트 + 라벨에 'AI 추정'
```

- **공식과 절대 섞지 않습니다.** `official=False`, 목록·상세·라벨 모두
  'AI 추정'과 확신도를 표시하고, 상세 화면에는 `공식 쉼터 아님` 배지가 붙습니다.
  `공식 지정 쉼터만 보기` 를 켜면 함께 사라집니다.
- **애매하면 띄우지 않습니다.** 확신도 62% 미만은 버립니다. 찾아갔는데 못 들어가는
  것이 아예 안 뜨는 것보다 나쁘기 때문입니다.
  실제로 `크래프톤타워`·`카카오 판교아지트`·`판교 테크원타워` 는 사무용 빌딩으로,
  `봇들마을 5단지 경로당` 은 단지 내 시설로 걸러집니다.
- **편의점·카페·은행·식당은 후보에서 뺐습니다.** 시험 삼아 넣었더니 판교역
  한 구역에서만 카페 10곳·편의점 9곳이 잡혀 정작 쓸모 있는 마트와 도서관이
  묻혔습니다. 구매나 용무가 전제인 곳은 '쉼터'로 안내하기 어렵습니다.
- **중복 제거는 이름으로 판단합니다.** 거리만 보면 안 됩니다 — 큰 건물 안에 다른
  시설이 입점한 경우가 흔해서, 홈플러스가 그 안의 농협 지점(16m)과 같은 곳으로
  묶여 지도에서 사라졌습니다. 마트를 띄우려던 기능이 마트를 지운 셈입니다.
- 판단은 **상호 단위로 영구 캐시**하고 한 번에 25곳씩 묶어 물어봅니다.
  구역당 Overpass 1회 + Gemini 1~3회면 채워지고, 이후로는 호출이 없습니다.
- 설정 → **추천 필터 → `지도에 이름이 있는 곳을 AI로 추가 판단`** 으로 끌 수 있습니다.
  Gemini 를 쓸 수 없으면(서버 연결 실패 등) 자동으로 비활성입니다.

### 6. 그 밖에
- **지도**: 드래그로 이동, 휠로 확대/축소, 마커 클릭 시 요약 패널, 더블클릭 시 상세.
  우측에 `추천순 / 가까운순 / 온도순 / 조용한순 / 눈치없는순` 정렬 목록.
- **AI 추천(챗)**: "지금 조용하고 시원한 곳", "밤 9시 이후에도 여는 곳",
  "이벤트 때문에 붐비는 곳 있어?" 같은 질문에 근거와 함께 답합니다.
- **즐겨찾기**: 하트 버튼으로 저장, 실시간 상태를 카드로 확인.
- **설정**: 표기 방식, 목표 온도(냉/난방 별도), 공식 쉼터만 보기, 최대 도보 시간,
  **기준 시각 시뮬레이션**(특정 시간·요일의 예측을 미리 확인), 애니메이션 on/off.
- 설정과 즐겨찾기는 `%APPDATA%\CoolMap\settings.json` 에 저장됩니다.

  ui/

    home.py              홈 (모드 전환 · 지도 미리보기 · AI 추천)
    mapcanvas.py         지도 렌더러 (하이라이트 / 화살표 마커)

## CoolMap 서버 (Supabase)

사용자가 API 키를 발급받지 않아도 앱이 실데이터로 동작하도록, 키가 필요한 호출은 서버가 대신합니다.
앱에는 **공개용 publishable key 만** 들어 있고(`providers/backend.py`), 실제 API 키는
Supabase Edge Function Secrets 에만 있습니다.

| 기능 | 서버 동작 | 앱 쪽 |
|---|---|---|
| 쉼터 | `sync-shelters` 가 매주 월 03:00(KST) safetydata 전량을 `shelters` 테이블에 동기화 | 테이블을 읽어 로컬 캐시 (약 11만 건, 수 초) |
| 날씨 | `weather` 가 기상청을 호출하고 격자별로 실황 30분 · 예보 3시간 캐시 | 격자 (nx, ny) 로 조회 |
| AI | `ai` 가 서버에 고정된 루브릭으로 Gemini 호출, 결과를 모든 사용자가 공유 | 시설 유형 값 · 상호명만 전송 |

남용 방지:
- 테이블은 RLS 로 앱에 **읽기만** 허용하고, 캐시 테이블은 아예 노출하지 않습니다.
- `ai` 는 **아무 질문이나 받지 않습니다.** 프롬프트는 서버가 정하고, 입력은 허용 목록으로 검사합니다.
- 기상청 신규 조회는 시간당 150회, Gemini 호출은 시간당 전체 120회 · IP당 40회로 제한합니다.
- 동기화 함수는 비밀 헤더(`x-sync-secret`)가 있어야만 실행됩니다.

루브릭 · 스키마 · 허용 목록은 `providers/gemini.py`, `candidates.py` 와 `supabase/functions/ai` 에
같은 내용이 있으므로 한쪽을 고치면 다른 쪽도 고쳐야 합니다.

## 현재 위치

**브라우저의 `navigator.geolocation` 은 웹 전용이라 이 앱에서는 쓸 수 없습니다.**
대신 3단계로 확보합니다.

1. **Qt Positioning** — PySide6 내장. Windows 에서는 `winrt` 백엔드가
   윈도우 위치 서비스(GPS·Wi-Fi·기지국)를 사용합니다. 추가 설치·키가 필요 없고
   실측 정확도는 수십~수백 m 수준입니다.
2. **IP 기반 추정** — 위치 권한이 꺼져 있거나 실패했을 때. 도시 수준(수 km) 근사치입니다.
3. **수동 지정** — 지도에서 **우클릭**하면 그 지점을 현재 위치로 삼습니다. 항상 동작합니다.

앱을 켜면 자동으로 1회 확인하고, 상단 바의 ◎ 버튼이나 지도의 위치 버튼으로 다시 확인합니다.
결과는 `settings.json` 에 저장돼 다음 실행 때 즉시 복원됩니다. 외부로 전송하지 않습니다.

> 위치가 잡히지 않으면 **Windows 설정 > 개인 정보 및 보안 > 위치** 에서
> '앱이 사용자 위치에 액세스하도록 허용'을 켜주세요.
> 설정 > 현재 위치 에서 현재 좌표와 사용 중인 백엔드를 확인할 수 있습니다.

## 쉼터 데이터

행정안전부 재난안전데이터공유플랫폼의 두 데이터셋을 모드별로 씁니다.

| 모드 | 서비스 ID | 건수 |
|---|---|---|
| 냉방 | `DSSP-IF-10942` 무더위쉼터 | 60,879 |
| 난방 | `DSSP-IF-10804` 한파쉼터 | 53,027 |

두 데이터셋은 **필드명이 전혀 다릅니다** (`RSTR_NM` vs `REARE_NM`, `LA/LO` vs `LAT/LOT`).
`Dataset` 명세에 원본 필드명을 매핑해 두고 내부에서는 공통 이름만 다룹니다.
한파쉼터는 평일 외에 **토·일·공휴일 운영시간**이 따로 있고, 시간 형식이
4자리(`0900`)와 6자리(`090000`)로 섞여 들어옵니다.

- 서버 측 필터가 없어 **전량을 1회 동기화**(각 25~40초)한 뒤 디스크에 캐시합니다.
  이후 실행은 즉시 로드되며, 2주가 지나면 자동으로 다시 받습니다.
- 화면에는 현재 위치 반경(기본 2.5km) 안의 쉼터만 올립니다. 설정에서 0.5~5km로 조절합니다.
- 원본 필드 매핑: `RSTR_NM`(명칭) · `LA`/`LO`(좌표) · `FCLTY_TY`(유형) ·
  `WKDAY_OPER_*`(운영시간) · 주말·야간 개방 플래그 · `AR`(면적).
- **에어컨 보유 대수(`COLR_HOLD_ARCNDTN`)와 이용가능인원(`USE_PSBL_NMPR`)은 표시하지 않습니다.**
  원본 신뢰도가 낮아 수치로 쓰기 어렵습니다. 냉방설비는 **유무만** 표기합니다.
- **실내 온도는 언제나 추정치입니다.** 시설 유형과 냉방설비 유무로만 추정하고,
  편의시설란에 "실내 온도는 추정치"를 항상 붙입니다.
- **일일 요청 한도가 있습니다.** 전량 동기화 1회가 약 60요청이라 반복하면 금방 소진됩니다.
  한도 초과(코드 22)나 키 문제(20/30/31)는 재시도해도 소용없으므로 즉시 중단하고,
  받은 만큼 저장한 뒤 못 받은 페이지만 다음에 이어받습니다. 실패 사유는 설정 화면에 표시됩니다.

## 참고 · 남은 작업

- 이벤트 데이터는 아직 데모입니다. 서울시 문화행사 API 또는 TourAPI 로 교체 가능합니다.
- OSM 타일은 이용 정책에 따라 식별 가능한 User-Agent 를 보내고 캐시를 사용합니다.
  대량 일괄 다운로드는 하지 않습니다. 저작자 표시(© OpenStreetMap contributors)는 지도에 항상 표기됩니다.
- Overpass 공개 인스턴스는 자주 죽고, 망에 따라 특정 호스트만 막히기도 합니다
  (개발 중 `overpass-api.de` 와 `kumi` 양쪽이 동시에 닿지 않는 상황을 만났습니다).
  `providers/overpass.py` 가 여러 미러를 순회하고 성공한 곳을 기억해 다음부터
  먼저 시도합니다. 지역 한정 인스턴스는 한국 질의에 빈 결과를 주므로 넣지 않았습니다 —
  조용히 아무것도 안 뜨는 게 실패보다 나쁩니다.
